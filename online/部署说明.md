# GIF Studio 网页版部署

这是静态网页工具。Mac 和 Windows 使用同一个 HTTPS 地址，通过浏览器选择本地视频、剪辑、缩放和压缩。文件在浏览器内处理，没有后端上传接口、账号服务或转换服务器。网站运营方无法通过本工具的正常转换流程获取用户选中的视频。

## 部署包

将 `GIF-Studio-Web-Deploy.zip` **完整解压**。`index.html` 必须位于网站发布目录根部，`vendor` 和其他文件保留原有相对位置。无需安装 Node.js、FFmpeg 或数据库。不能直接双击本地 HTML 使用，必须通过 HTTP / HTTPS 服务打开。

### GitHub Pages（源码自动部署）

使用单独的 `GIF-Studio-GitHub-Source.zip`：解压后将全部内容提交到 GitHub 仓库根目录，包含 `.github`。在仓库 Settings → Pages 中将 Source 设为 GitHub Actions，再运行 Actions 中的 `Deploy GIF Studio to GitHub Pages`。工作流会自动安装依赖、构建和检查，并发布为一个 HTTPS 网站。无需自行上传 31 MB 的 WASM，也无需配置个人 Token。

GitHub Free 使用公开仓库。详细步骤见源码包的 README 或项目 `online/GITHUB-PAGES.md`。普通地址形式是 `https://用户名.github.io/仓库名/`；以部署结果显示的地址为准。

### Netlify

登录自己的 Netlify 账号，在新增站点的手动部署区域上传解压后的完整目录，等待部署完成，使用平台分配的 HTTPS 地址。更新时重新上传完整目录。包内已带缓存和安全响应头配置。

### Vercel

在自己的 Vercel 项目中将解压后的目录作为静态网站发布目录，不设置构建命令。也可以在该目录使用已登录的 Vercel CLI 运行 `vercel --prod`。包内已带响应头配置。

### 自有服务器

解压后放到 Nginx / Caddy / Apache 的网站目录，配置 HTTPS，并确保 `.js` 响应为 JavaScript、`.wasm` 响应为 `application/wasm`。也可使用附带 Dockerfile：

```
docker build -t gif-studio-web .
docker run -d --name gif-studio-web -p 8080:80 gif-studio-web
```

在域名的 HTTPS 反向代理后转发到服务器的 8080 端口。Docker 命令只启动静态文件服务，不会开放用户电脑的任何目录。

首次使用转换程序需要下载约 31 MB。托管平台须允许发布这一大小的 WASM 静态文件；若平台对单文件有更小的限制，请改用其他静态托管或自有服务器。

## 使用限制

- 建议使用当前版本的 Chrome / Edge；Safari / Firefox 使用标准下载保存。实际浏览器兼容性需在目标机器验收。
- 支持选择目录的浏览器可通过用户授权写入所选文件夹；保存的是目录句柄而非任意磁盘路径。重开网页后可能需要再次授权。无法选择目录时，点击“下载 GIF”。网页不能像桌面工具那样按输入的绝对路径直接写文件。
- 文件上限 200 MB，单次截取 0.1–120 秒。过大的尺寸、帧率和时长组合会要求减小设置。浏览器版通常比桌面版慢，转换期间请保持页面打开。
- 选择的源文件和生成的 GIF 存放在当前标签页内存；刷新或关闭会丢失未下载的结果。不会静默写入未获授权的磁盘目录。
- 调整起止点时保持源视频比例预览。浏览器无法解码的格式使用 WASM 抽帧，更新可能有延迟。
- 不依赖运行中的本地服务，也不依赖第三方 CDN。访问网站产生的静态文件下载流量按托管平台套餐计费。
